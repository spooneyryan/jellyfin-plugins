Web client

When off, the web client shows no bookmark buttons, sections or pages; the REST API keeps working. Applies the next time a page is loaded.
When a Jellyfin update moves a part of the web client that Bookmarks adds its buttons to, browsers report it: the server log gets one warning, and the Diagnostics tab lists the reports.

Pages

Each user's page of all their bookmarks, with search, filters, renaming and their naming options, linked under Library tools in the menu, from a video's bookmarks and from the player's list. When off, no link leads to it and it says the server admin turned it off. Applies the next time a page is loaded.
Each user's page of all their clips, those of deleted bookmarks included, with their state (ready, being made, failed, file missing, clip folder offline), linked under Library tools in the menu, from My Bookmarks, a video's bookmarks, the player's list and the clip-ready message. While it is on, deleting a bookmark keeps its clip unless "Also delete its clip" is ticked, since My Clips lists kept clips. When off, no link leads to it, it says the server admin turned it off, and deleting a bookmark deletes its clip unless that box is unticked. Applies the next time a page is loaded.
The Plugin Pages choices need the Plugin Pages plugin, and apply after the server restarts.
Only in the two Plugin Pages choices above. Applies after the server restarts (Plugin Pages can't take a page back while it runs).
The section above User in the menu with the links to My Bookmarks and My Clips. When off, the pages are still reached from a video's bookmarks, the player's list and each other.

Player

The three buttons next to the player's controls: bookmark this moment, mark a range, this video's bookmarks. The bookmark shortcut works either way. Applies the next time a video is played.
The key that bookmarks the current moment while a video plays, with any modifiers: Shift+B (the default, since Jellyfin Enhanced takes B), F7 or Ctrl+Alt+M. Empty turns it off. Each user can choose their own on their device, under My Bookmarks, Player options.
The default for users who haven't chosen for themselves: the name dialog opens at once after the shortcut or the bookmark button. When off, a toast offers "Name it" instead and playback goes on. Each user can change this with the dialog's "Always ask for a name" or under My Bookmarks, Player options.
The name dialog starts with the title of the chapter the bookmark is in, selected, so typing replaces it. Names Jellyfin or a ripper made up ("Chapter 3", a time) are never suggested.

Jellyfin Enhanced

The banner at the top of this page while Jellyfin Enhanced has its own bookmarks switched on, so there are two bookmark systems. The import of its bookmarks and the checklist to switch them off are on the Data tab either way.

Bookmark data

A kept clip file stays with what is left of its bookmark, for admins only. Applied only when Jellyfin deletes a user, never to bookmarks of a user the server just doesn't know (the Data tab lists those).
A bookmark whose video left the library waits as "Not in library" and comes back with the video. 0 (the default) keeps it so for good. A number of days moves one gone that long into the archive (data/bookmarks/archive), where it still finds its video again; nothing is ever deleted on a timer, and a bookmark with a clip file is never archived.
The daily maintenance (03:10) copies the bookmark data to data/bookmarks/snapshots and keeps this many copies; 0 takes none. The Data tab lists them and restores one.

Clips

Users can extract the range between a bookmark's start and end into a video file. Creating and downloading clips requires the user's Allow media downloading permission.

On, admins get an "All users" view on the My Clips page: every user's clips with their owners, names and file paths, which they can preview, download, cancel and delete. Bookmark notes are never shown, but a clip without a name has the start of its note in its file name. Off, admins see only their own clips there; the per-user totals stay.
Where clips are saved on the server. Leave it empty for data/bookmarks/clips in the server's data folder, outside every library: the right choice unless clips should be browsable in Jellyfin.
To browse clips in Jellyfin, make a folder of their own on a drive with plenty of free space, add a library of type Home Videos and Photos for exactly that folder, and enter the folder here. Never use a Movies or TV library, or a folder inside any library: Jellyfin takes clips there for the film or episode they come from and shows them as duplicates. Everyone who can open the clip library sees every user's clips; for private clips keep the default folder.
A clip is refused when it, and the clips waiting to be made, would leave less than this free on the clip folder's drive, and a clip being made is stopped when less than half of it is left. 0 keeps nothing free: a clip is then refused only when it wouldn't fit.
0 means no limit.
Other clips wait in a queue. Takes effect after the server restarts.
A clip being made is written as a .partial file. If the server stops without finishing it (a crash), the next start deletes that file before the clip is made again. Only files named as Bookmarks names them, in the clip folders, are deleted; other programs' .partial files are never touched.
The daily maintenance marks a clip whose file is gone from its clip folder (deleted by hand, or through Jellyfin) as missing, and clears the mark when the file is back. After this many days (at most 36500) a deleted bookmark's kept clip moves into the archive (data/bookmarks/archive), and a bookmark's own clip is forgotten while the bookmark stays; no file is ever deleted. 0 keeps them for good. Clips are marked only in a clip folder Bookmarks recognises as theirs, by the marker file it keeps in it (.jfbm-clip-root): a folder that isn't there (an unplugged drive), that is there without its marker and without all of its clips (a disk or share that isn't mounted, a folder in its place), or in which every clip is gone at once is left out, and the Diagnostics tab names it, so nothing in it is marked or archived. If a folder's clips are gone for good, confirm it there: its clips are then marked missing.

Accurate clip encoding

Slower presets produce smaller files at the same quality but take longer.
Lower is better quality and larger files. 18 is visually lossless for most content; 23 is x264's default.

Import from Jellyfin Enhanced

Copies every user's Jellyfin Enhanced bookmarks into Bookmarks: labels become names and positions are kept, each on the video it was made on (or the one with the same TMDb id), and bookmarks of videos that aren't in the library are kept as "Not in library" until they are. Jellyfin Enhanced's files and settings are only read. The dry run shows what the import would do and changes nothing; running the import again adds only what is new.

Switch off Jellyfin Enhanced's bookmarks

What to switch off in Jellyfin Enhanced once its bookmarks are imported, so there is one bookmark system, in this order: the shortcut comes last, so a restart can't bring its B back unnoticed. Each item is ticked as soon as the server sees the change; what stays until a restart is said next to it.

    Export and import

    Jellyfin's own backups leave plugin data out. An export saves every user's bookmarks with their names and notes (keep the file safe), what is left of bookmarks deleted with their clip kept, the naming preferences and the Jellyfin Enhanced import's record, in one file; an import reads such a file back, here or on another server. Clip files themselves are not in it.

    Snapshots

    The daily maintenance keeps a copy of the bookmark data every day (Daily snapshots to keep, on the Settings tab), and a copy is taken before every import, restore and other change of many bookmarks at once. Restoring a snapshot makes every bookmark the snapshot's, after a copy of the data as it is now.

    Users this server doesn't know

    Bookmarks of user ids that aren't on this server: a user deleted while Bookmarks was off, or data restored from another server. Nothing is deleted on its own. Remap by name gives each of them to the user of this server with the same name; the deleted-user policy (Settings tab) treats them as deleted users.

    Bookmarks per user

    How many bookmarks each user has, and of which kind. Admins see counts only, never a bookmark's name, note or video.

    Web client problems reported by browsers

    Parts of the web client Bookmarks relies on that a browser couldn't find since the server started, so the Bookmarks feature that uses them was off there. A Jellyfin update is the usual cause; a Bookmarks update brings the fix.
